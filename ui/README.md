# Alchemy UI

Web UI for Alchemy, built with Vite + React + [@galaxy-io/dls](https://www.npmjs.com/package/@galaxy-io/dls), talking to the ConnectRPC `FunctionsService` and `MetricsService` that `server` serves.

## Develop

```bash
just dev   # from the repository root: host, server and the UI on http://localhost:5173
just ui    # the UI alone, against a server already running on :8780
```

The dev server proxies `/functions.v1.FunctionsService` and `/metrics.v1.MetricsService` to `server` on `http://localhost:8780`, so the app calls the API on its own origin. Set `VITE_API_URL` to point it somewhere else. `just example` and `just demo` register and invoke the embed functions, which gives every screen something to show.

## Codegen

TypeScript clients are generated from the repository's `protos/functions` and `protos/metrics` into `src/gen/` (checked in):

```bash
pnpm codegen   # buf generate; `just ui-gen` from the root
```

Arrow contracts carry their schemas and payloads as Arrow IPC streams; `src/utils/arrow.ts` reads and writes them with `apache-arrow`, so the contract tab shows the fields and the playground takes and returns JSON rows. `src/routeTree.gen.ts` is generated by the TanStack Router plugin during `pnpm dev` / `pnpm build` and is checked in.

## Module and host

One source tree, two outputs.

- `pnpm dev` / `pnpm build` is the standalone app (`build/`): `index.html`, `src/main.tsx`, the router and the file routes under `src/routes/`, the command palette under `src/layouts/app`, the transport and query client under `src/api/`. This is the **host**.
- `pnpm build:lib` is the `@galaxy-io/alchemy` module (`dist/`, published through the `exports` in `package.json`): the island with its sidebar (`src/layouts/main`), the screens, their hooks and query layer, the generated clients, and the public surface under `src/module/`. A bigger app such as Galaxy mounts it under its own router and providers, inside whatever product-level navigation it has; the module fills the box it is given.

The module never imports the host. A biome override (`noRestrictedImports`) fails the build when library code reaches `src/routes`, `src/router.tsx`, `src/layouts/app`, the transport, the query client or `src/pages/NotFoundPage.tsx`.

A host mounts the module with one file route per screen. Route contents come from `@galaxy-io/alchemy/routes` and the page from `@galaxy-io/alchemy/pages/...`, so the router plugin still code-splits each page:

```ts
// routes/_app/functions/route.tsx: the island, the overlays, the search params they open from, and the module's base
export const Route = createFileRoute("/_app/functions")({ ...alchemyLayoutRoute, component: AlchemyLayout });

// routes/_app/functions/images/$id.tsx
export const Route = createFileRoute("/_app/functions/images/$id")({ ...functionRoute, component: FunctionPage });
```

The module never hardcodes its mount path. `useAlchemyBase()` reads it from the layout route, `useAlchemyNavigate()` and `RouterLink` resolve relative targets such as `./images/$id` against it, and `useAlchemyCommandItems({ base })` gives the host's command palette the module's items; pass the mount path as `base` when the palette is also open outside the module, since only a page inside it knows the base. Screens write their search params through `useAlchemySearchUpdate`, typed by the module's schemas, because the module cannot name the host's routes; `pnpm typecheck:lib` checks the sources the way a host compiles them, without this app's route tree. The host installs the module's peer dependencies (`package.json#peerDependencies`), renders `GalaxyProvider`, `TransportProvider` and `QueryClientProvider` once and imports `@galaxy-io/alchemy/styles.css` next to the DLS stylesheets. The screens suspend on their queries, so the host's router needs a `defaultPendingComponent` (`@galaxy-io/alchemy/layouts/PendingLayout` works) and its query client must not retry `NotFound`, `PermissionDenied`, `Unauthenticated` or `InvalidArgument`, as `src/api/queryClient.ts` does; otherwise a missing function suspends the whole tree instead of rendering the not-found page. Linaria classes are prefixed `alchemy-`.

## Gates

```bash
pnpm typecheck
pnpm typecheck:lib   # the module's sources without the host's route tree
pnpm lint:check
pnpm format:check
pnpm build
pnpm build:lib
pnpm check:package
```

## Conventions

Everything in `src/` follows Filament's `filament-ui` skill (`filament/.agents/skills/filament-ui`): DLS components by subpath, Linaria with DLS tokens, no margins, no barrels, feature-prefixed files, URL-backed view state, the query layer in `src/api/queries`.
